# 微信文章排版规则

## 字号

| 元素 | 字号 | 行高 |
|---|---|---|
| 正文 | 16px | 1.8 |
| H1 | 24px | 1.35 |
| H2 | 20px | 1.4 |
| H3 | 17px | 1.5 |
| 图卡面板标题 | 16px | 1.45 |
| 图卡标题 | 14.5px | 1.45 |
| 图卡说明 | 12.5px | 1.65 |
| 图卡标签 | 11px | 1.5 |
| pill / 等宽小标签 | 11.5px | 1.5 |
| 行内代码 | 0.88em | 继承 |

`scripts/build_html.py` 的 `tune_type()` 会把组件里的 15/13.5/11.5/10.5/10px 统一上调一档;正文、H1/H2/H3 不动。不要在正文里硬写 11px 以下的小字。

## 标点

- 中文正文用全角:`，``；``：``？``！`
- 中文引号用 `“ ”`,不要用直引号 `" "`
- 含中文的括号用全角 `（ ）`;纯英文/版本号可保留半角 `(v7.4.0-rc1)`
- 跳过 `<code>`、URL、HTML 标签属性;代码里的 ASCII 标点保持原样
- 中英文之间保留空格:`GPU HBM`、`chunk × object group`、`4KB 读写`

构建器已经处理这些;手写 `:::html` 时也尽量保持同样风格。

## 行内代码

- `font-size:0.88em`,浅灰背景,无边框,`padding:0 3px`
- ≤40 字符:`white-space:nowrap`,整词换行,避免 `bi_vc/nt`
- >40 字符:允许 `overflow-wrap:break-word`
- 长标识符宁可整体换行,也不要拆成两半
- 代码里的 `, ; :` 不要被中文标点转换

## 图卡布局

优先纵向,手机宽度约 350px:

- 分层/流程:卡片自上而下,卡间居中 `↓ 下一步动作`
- 介质视图:每个介质一张卡,卡内放 unit pills;卡间写 `store_kv` / `L2 读`
- 字段/元数据:每个字段一张小卡(左色条 + 等宽标签 + 说明)
- 两态对照:每层一张卡,卡内 READ / WRITE 两条浅色条
- 映射:`offset → index → folio` 用 pill + 文字箭头
- 回载:2×2 路径块,行间 `↓`,不要让箭头吊在行尾

不要用 `<table>` 表达数据视图;字段清单也不要做成“无边框表格”(两列 + 虚线)。两列只在内容确实需要并排对比、且宽度足够时使用。

## 文字与图的一致性

- 图里如果是灰色箭头,正文不要写“蓝线/黄线”
- 图里是纵向排列,正文不要写“从左往右”
- 面板标题不要和 H2 完全重复;面板标题应补充信息
- 颜色只表示层级/介质,不表示“数据是否搬运”;需要说明时写在图注或 figcaption
- 术语统一:`folio`、`bio_vec`、`MemoryObj`、`placement` 保持原样

## 常见问题

| 现象 | 处理 |
|---|---|
| 代码断成 `bi_vc/nt` | 短词 `white-space:nowrap` |
| 中文逗号显示很挤 | 全角标点 |
| 直引号很丑 | 中文引号 `“ ”` |
| 表格在手机上很窄 | 改成字段卡/流程卡 |
| 标题和面板标题重复 | 面板标题写“这图新增的信息” |
| 回载箭头吊在行尾 | 拆成 2×2 或纵向 |
| 大段字段两列像表格 | 每个字段一张卡 |
| 组件字号偏小 | 用 `tune_type` 或整体上调一档 |

## 发布前检查

1. 390px 无横向溢出
2. 标题不孤字,代码不断词
3. 组件字号 ≥11px,说明 ≥12.5px
4. 全角标点/中文引号;代码与 URL 未被转换
5. `table=0 img=0 class=0 script=0 style 标签=0`
6. 「阅读原文」URL 返回 200
7. 草稿箱预览确认后才群发
